# FastAPI User Auth

[![CI](https://github.com/Muhammad-Tayyab1/fastapi-user-auth/actions/workflows/ci.yml/badge.svg)](https://github.com/Muhammad-Tayyab1/fastapi-user-auth/actions/workflows/ci.yml)

An asynchronous REST API for user authentication and account management, built with FastAPI, PostgreSQL, and SQLModel. It provides email OTP verification through Resend, JWT access and refresh tokens, password recovery, role-based administration, and user-owned notes CRUD.

## Features

- Registration with six-digit email OTP verification
- Secure password hashing with bcrypt
- JWT access and refresh tokens
- Login, token refresh, and password-reset flows
- OTP expiry, single use, resend throttling, and failed-attempt lockout
- Rate limits by client IP and email for sensitive endpoints
- Self-service profile updates and soft account deletion
- Role-based administrator endpoints
- User-owned notes with CRUD and ownership isolation
- Async PostgreSQL access through SQLModel and asyncpg
- Versioned Alembic database migrations
- OpenAPI documentation generated by FastAPI
- Docker Compose configuration for local PostgreSQL
- Async integration tests and GitHub Actions CI

## Requirements

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/)
- PostgreSQL 14 or newer, or Docker with Compose
- A Resend account and verified sender domain for real email delivery

## Local setup

```bash
git clone https://github.com/Muhammad-Tayyab1/fastapi-user-auth.git
cd fastapi-user-auth
uv sync --dev
cp .env.example .env
docker compose up -d postgres
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`.

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`
- OpenAPI JSON: `http://127.0.0.1:8000/openapi.json`

## Configuration

Settings are loaded from environment variables or `.env`.

| Variable | Example | Description |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql+asyncpg://user:pass@localhost:5432/authdb` | Async database URL |
| `JWT_SECRET` | long random value | Secret used to sign tokens |
| `JWT_ALGORITHM` | `HS256` | JWT signing algorithm |
| `ACCESS_TOKEN_EXPIRE_MIN` | `30` | Access-token lifetime in minutes |
| `REFRESH_TOKEN_EXPIRE_DAYS` | `7` | Refresh-token lifetime in days |
| `OTP_EXPIRE_MIN` | `5` | OTP lifetime in minutes |
| `OTP_MAX_RESEND_PER_HOUR` | `3` | Resend/reset requests allowed per hour |
| `REGISTER_MAX_PER_HOUR` | `5` | Registration requests allowed per hour |
| `LOGIN_MAX_PER_15_MIN` | `10` | Login attempts allowed per 15 minutes |
| `RESEND_API_KEY` | `re_xxx` | Resend API key |
| `EMAIL_FROM` | `onboarding@yourdomain.com` | Verified sender address |
| `CORS_ORIGINS` | `["http://localhost:3000"]` | JSON list of allowed browser origins |

Generate a JWT secret with:

```bash
openssl rand -hex 32
```

When `RESEND_API_KEY` is empty, email delivery is skipped. The OTP is still stored for automated tests, but clients cannot complete live registration without email delivery.

## API endpoints

### Authentication

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/auth/register` | Public | Register or restart an unverified registration |
| `POST` | `/auth/verify-otp` | Public | Verify registration and issue tokens |
| `POST` | `/auth/resend-otp` | Public | Replace and resend the registration OTP |
| `POST` | `/auth/login` | Public | Authenticate and issue tokens |
| `POST` | `/auth/refresh` | Refresh token | Issue a new token pair |
| `POST` | `/auth/forgot-password` | Public | Send a password-reset OTP |
| `POST` | `/auth/reset-password` | Public | Validate the OTP and replace the password |

### Users

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/users/me` | User | Read the current profile |
| `PATCH` | `/users/me` | User | Update the current profile |
| `DELETE` | `/users/me` | User | Soft-delete the current account |
| `GET` | `/users/` | Admin | List users with pagination |
| `GET` | `/users/{user_id}` | Admin | Read a user |
| `PATCH` | `/users/{user_id}/role` | Admin | Set the `user` or `admin` role |

### Notes

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/notes/` | User | Create a note |
| `GET` | `/notes/` | User | List the current user's notes |
| `GET` | `/notes/{note_id}` | User | Read an owned note |
| `PATCH` | `/notes/{note_id}` | User | Update an owned note |
| `DELETE` | `/notes/{note_id}` | User | Delete an owned note |

Access to another user's note returns `404`, preventing ownership information from being disclosed.

## Example authentication flow

Register:

```bash
curl -X POST http://127.0.0.1:8000/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"person@example.com","password":"a-strong-password","full_name":"Example User"}'
```

Verify the emailed OTP:

```bash
curl -X POST http://127.0.0.1:8000/auth/verify-otp \
  -H 'Content-Type: application/json' \
  -d '{"email":"person@example.com","code":"123456"}'
```

Use the returned access token on protected endpoints:

```bash
curl http://127.0.0.1:8000/users/me \
  -H "Authorization: Bearer ACCESS_TOKEN"
```

Create a note:

```bash
curl -X POST http://127.0.0.1:8000/notes/ \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"My first note","content":"Private user content"}'
```

## Testing

```bash
uv run pytest -q
```

Tests use an isolated async SQLite database and do not send email. Coverage includes password hashing, JWTs, OTPs, registration, verification, login, token refresh, profile access, password reset, rate limiting, note CRUD, and cross-user ownership isolation.

GitHub Actions runs the tests and validates offline migration generation on every push and pull request.

## Administrator setup

Registration always creates the `user` role. Promote the first administrator through a trusted database operation or deployment script; there is intentionally no public admin-creation endpoint. An administrator can then use `PATCH /users/{user_id}/role` for later role changes.

## Security and production

- Replace the example JWT secret and use HTTPS.
- Configure an explicit production CORS allowlist.
- Verify `EMAIL_FROM` in Resend before enabling delivery.
- Use Redis-backed rate limiting when running multiple workers or replicas.
- Configure trusted proxy handling at the server boundary; the application does not trust `X-Forwarded-For` by default.
- Store secrets in a managed secret store rather than committing `.env`.
- Add refresh-token rotation/revocation if immediate logout or session management is required.
- Configure backups, monitoring, structured logging, and perimeter rate limiting.
